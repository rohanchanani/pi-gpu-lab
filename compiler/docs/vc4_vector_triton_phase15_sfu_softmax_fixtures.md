# Phase 15 Controlled Triton SFU/Softmax Fixtures

Phase 15.2 adds source-controlled real Triton fixtures and emitted TTIR
snapshots for the approximate-SFU math and one-block softmax contract.

The accepted snapshots are narrow:

- f32 `tl.exp` as public natural `math.exp` at the value surface; Phase 15B
  requires the value lowering to scale natural exp through target exp2;
- f32 reciprocal/division as `arith.divf` under an explicit approximate-SFU
  policy;
- finite f32 `tl.max` as `tt.reduce` with an `arith.maxnumf` combiner;
- one-block stable softmax for `1 <= ncols <= 16`;
- mixed f16-storage input softmax with f32 compute/output;
- optional `tl.log` and `tl.rsqrt`; Phase 15B classifies public `tl.log` as
  natural log lowered through target log2 scaling, while `rsqrt` maps to the
  target reciprocal-square-root mode under positive finite policy.

Accepted fixtures exclude `tl.dot`, `tt.dot`, `vector.contract`, atomics, block
pointers, full attention, FlashAttention, multiblock softmax, fp-to-int casts,
native f16 arithmetic, bf16/fp8, and quantized int storage.

Exact/default math remains staged because VC4 SFU lowering is approximate and
requires explicit policy. Zero-active softmax remains staged unless a later
phase introduces and proves a finite no-op guard. Multiblock softmax remains
staged outside the one-block v0 contract.

The snapshots are generated by the existing pinned Triton v3.7.0 wrapper:

`.vc4_auto/vector_triton_phase85r15_generator_restore/run_vc4_emit_ttir.sh`

No compiler semantic source changes are part of this fixture-design package,
and global Triton readiness remains `NO`.
