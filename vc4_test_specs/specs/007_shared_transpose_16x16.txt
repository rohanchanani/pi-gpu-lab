TEST_NAME: shared_transpose_16x16
TEST_KIND: hardware-run
ONE_SENTENCE_PURPOSE: Validate a fixed 16x16 uint32 transpose using VPM as CUDA-like shared memory, vertical VPM reads, and the reusable semaphore barrier.

WHY_THIS_TEST_NOW:
The previous shared-memory tests established VPM visibility and reusable barriers, and matmul_blocked established useful VPM tiling in a compute kernel. A 16x16 transpose is the canonical next shared-memory orientation test: it writes rows into shared memory, synchronizes, reads columns as vectors, and stores transposed rows. This tests a VC4-specific shared-memory pattern that maps naturally to the documented VPM horizontal/vertical access modes.

SEMANTICS:
Given one fixed 16x16 matrix of uint32_t, compute its transpose exactly: output[row_out][col_out] = input[col_out][row_out]. The flattened public input and output buffers are row-major 256-word arrays. The reference kernel uses one cooperative block of four logical QPU warps. Each warp stages four input rows into VPM rows 0..15, all warps synchronize with the locked four-semaphore barrier, and then each warp reads four output rows through vertical 32-bit VPM reads, where output row c is VPM column c read from rows 0..15. The host verifies exact integer equality against a CPU reference.

PUBLIC_LAUNCH_API:
Expose only a semantic runtime API in shared_transpose_16x16_launch.h: int shared_transpose_16x16_prepare(struct vc4_runtime *rt, struct shared_transpose_16x16_state *state); int shared_transpose_16x16_launch(struct shared_transpose_16x16_state *state, const uint32_t input[256], uint32_t output[256]); and void shared_transpose_16x16_shutdown(struct shared_transpose_16x16_state *state). Do not expose qpu_id, logical warp id, raw uniforms, VPM rows, semaphore IDs, scheduler registers, code addresses, or hardware bus addresses in the public API.

RUNTIME_SETUP_REQUIREMENTS:
Use one GPU allocation and one code copy for the entire test. Prepare enables QPUs through vc4_runtime_init, sets or verifies V3D_VPMBASE=16 while idle if the existing runtime helper exposes that path, copies shared_transpose_16x16shader once, allocates scratch for one 256-word input, one guarded 256-word output, four uniform streams, and any result/status words, and records runtime_allocations=1. Each launch copies a fresh input tile into the already allocated scratch, initializes output sentinels in the already allocated output scratch, updates four uniform streams, queues four QPU requests as one resident cooperative block, waits for completion, copies back exactly 256 output words, and records runtime_launches. The harness runs four deterministic cases under this single allocation. Do not allocate/free/copy code inside each semantic launch.

QPU_KERNEL_SHAPE:
Uniforms should include input base, output base, logical_warp_id in 0..3, warps_per_block=4, vpm_base_row=0, arrive/release/depart/reset semaphore IDs for block 0 or static semaphore use 0..3, and any physical qpu_id/num_qpus suffix fields needed by existing launcher style. Each QPU uses ELEMENT_NUMBER as lane. For local_row=0..3, compute row = logical_warp_id*4 + local_row, issue TMU direct memory loads for input[row*16 + lane], and write the 16-lane vector to horizontal VPM row row using generic 32-bit horizontal VPM write setup 0x00001a00 | row. After all four rows are staged, execute the known four-semaphore reusable barrier for N=4 using semaphores 0..3. Then for local_col=0..3, compute output_row = logical_warp_id*4 + local_col, program a vertical 32-bit VPM read of one vector at X=output_row and Y=0 using the documented VPM vertical 32-bit address encoding ADDR[5:0] = {Y[5:4], X[3:0]}, wait at least three instructions, read VPM_READ, and store that vector as one coalesced output row at output + output_row*16*4 through VPM staging plus VDW. Protect VPM setup/access and VDW setup/store/wait with the global mutex except for the intentional semaphore barrier operations. Final program end must be nop; thrend followed by two nops.

TEST_CASES:
Run exactly four deterministic 16x16 input patterns under one runtime allocation: case 0 input[row][col] = row*16 + col; case 1 input[row][col] = 0x70000000 | (row << 8) | col; case 2 input[row][col] = row*37 + col*11 + 5; case 3 input[row][col] has 0xf0000000 | row on the main diagonal, 0xe0000000 | col on the anti-diagonal, and a small deterministic background elsewhere. Each case invokes the same already resident qasm code with updated input/output scratch and uniforms.

NON_GOALS:
This test does not support arbitrary matrix sizes, byte/halfword transpose, bank-conflict optimization, arbitrary shared-memory scatter/gather, or performance-tuned transpose. It does not decide VPM setup-sharing behavior; VPM/VDW setup remains mutex-protected. It is one fixed 16x16 tile that specifically validates row staging, barrier, vertical VPM readback, and coalesced output stores.
