TEST_NAME: stencil2d_5point_shared
TEST_KIND: hardware-run
ONE_SENTENCE_PURPOSE: Validate a small shared-memory five-point stencil tile using VPM rows for a block-local halo and the four-semaphore barrier.

WHY_THIS_TEST_NOW:
The naive stencil validates 2D indexing and multiple TMU loads. The shared version is the CUDA-like next step: cooperatively stage a tile into shared memory, synchronize, and compute interior outputs from VPM. This tests shared-memory halos, barrier participation, VPM row allocation, and coalesced stores in a scientific-computing pattern.

SEMANTICS:
Compute the same five-point stencil as `stencil2d_5point_naive`, but for a fixed small tile staged in VPM. The core case should compute a `10 x 14` interior output tile from a `12 x 16` VPM tile that includes a one-cell halo on all sides. Lane 0 and lane 15 are halo columns; logical warps 0 and 11 are halo rows; interior warps 1..10 and lanes 1..14 compute output. Boundary behavior is clamp-to-edge for global image boundaries. The harness compares against the CPU stencil for the tile region.

PUBLIC_LAUNCH_API:
Expose `int stencil2d_5point_shared_prepare(struct vc4_runtime *rt, struct stencil2d_5point_shared_state *state, uint32_t max_width, uint32_t max_height);`, `int stencil2d_5point_shared_launch(struct stencil2d_5point_shared_state *state, const float *input, float *output, uint32_t width, uint32_t height, uint32_t tile_origin_x, uint32_t tile_origin_y, float center_weight, float neighbor_weight);`, and shutdown. Keep VPM rows and semaphore IDs private.

RUNTIME_SETUP_REQUIREMENTS:
Use one allocation and one code copy. The launcher schedules one cooperative 12-warp block per tile test, VPM rows 0..11 for the staged tile plus a reserved staging row for output stores, and semaphores 0..3. All warps in the block must be enqueued together. Repeated cases update uniforms and payloads in the same allocation. Check ERRSTAT before/after.

QPU_KERNEL_SHAPE:
Each warp loads one global image row into the corresponding VPM row using TMU direct loads for lanes 0..15. The global row/column for each lane is derived from tile origin plus halo offset and clamped to image bounds. After all rows are written to VPM, execute the four-semaphore barrier. Interior warps and lanes then read center, north, south, west, and east values from VPM; west/east may use lane rotations or adjacent VPM access, but must not use global TMU loads except as a documented fallback. Store only the 10x14 interior tile outputs to the correct global output positions, preferably as coalesced row segments with guard handling. Use mutex around VPM/VDW setup/access.

TEST_CASES:
Use a small image such as `width=18,height=14` with tile origin `(0,0)`, a larger odd image `width=31,height=19` with tile origin `(3,2)`, and an edge tile touching the right/bottom boundary. Keep all cases within one resident block each. Deterministic input values should make CPU verification straightforward.

EXPECTED_OUTPUT:
Print `STENCIL2D_5POINT_SHARED_RUNTIME_SETUP max_width=31 max_height=19 allocations=1 warps_per_block=12`. Print per-case lines: `STENCIL2D_5POINT_SHARED_CASE case=<id> width=<w> height=<h> origin_x=<x> origin_y=<y> mismatches=0 sentinel_mismatches=0 checksum=<value> max_abs_diff=<value> launches=<count> allocations=1`. Final line: `VC4_TEST_RESULT name=stencil2d_5point_shared status=PASS cases=3 total_mismatches=0 sentinel_mismatches=0 launch_failures=0 active_qpus=12 lanes=16 warps_per_block=12 max_abs_diff=<value> runtime_allocations=1 runtime_launches=3 timeouts=0 errstat_relevant_changed=0 elapsed_usec=<time>`.

EXPECTED_JSON_ORACLE:
Require exact `name`, `status`, `cases=3`, `total_mismatches=0`, `sentinel_mismatches=0`, `launch_failures=0`, `active_qpus=12`, `lanes=16`, `warps_per_block=12`, `runtime_allocations=1`, `runtime_launches=3`, `timeouts=0`, and `errstat_relevant_changed=0`. Add `float_max.max_abs_diff = 0.001`.

NON_GOALS:
This test is not a general tiled stencil scheduler and does not cover multiple resident shared-memory blocks. It intentionally uses a fixed tile shape that maps well to 12 QPUs and 16 lanes.

SPECIAL_NOTES:
If VPM lane-rotation or adjacent-column reads are difficult, the model may implement a documented fallback that stages the 12x16 tile and still uses VPM for center/north/south while using TMU for horizontal halo; but the preferred implementation should consume all five stencil values from VPM after the barrier.
