TEST_NAME: image_sobel_3x3
TEST_KIND: hardware-run
ONE_SENTENCE_PURPOSE: Validate a naive grayscale Sobel edge-detection kernel with 3x3 neighborhood TMU loads and exact integer output.

WHY_THIS_TEST_NOW:
Sobel is a canonical image-processing kernel and a concrete 3x3 stencil with signed arithmetic and boundary handling. The naive/direct-load version should precede shared-memory image filters. It tests 2D indexing, multiple neighbor loads, integer math, absolute-value-like logic, clamp/saturate, and coalesced stores.

SEMANTICS:
Input is a row-major grayscale image stored as `uint32_t` values in the low 8 bits. For each pixel, use clamp-to-edge boundary handling and compute Sobel gradients:
`gx = -p00 + p02 - 2*p10 + 2*p12 - p20 + p22`
`gy = -p00 - 2*p01 - p02 + p20 + 2*p21 + p22`
Output `min(255, abs(gx) + abs(gy))` as a `uint32_t`. The CPU reference uses exact integer arithmetic.

PUBLIC_LAUNCH_API:
Expose `int image_sobel_3x3_prepare(struct vc4_runtime *rt, struct image_sobel_3x3_state *state, uint32_t max_width, uint32_t max_height);`, `int image_sobel_3x3_launch(struct image_sobel_3x3_state *state, const uint32_t *input, uint32_t *output, uint32_t width, uint32_t height);`, and shutdown. Public arguments are semantic image buffers and dimensions only.

RUNTIME_SETUP_REQUIREMENTS:
Use one allocation and one code copy. Allocate input/output scratch sized for max image and guard words. Each launch copies the current input, initializes output sentinel guard, updates uniforms, queues active QPUs, and copies back `width*height` outputs. Use repeated launches for multiple images under one runtime setup.

QPU_KERNEL_SHAPE:
Uniforms: input base, output base, width, height, total_pixels, qpu_id, num_qpus. Each lane maps a flat pixel index to `(y,x)`, computes clamped 3x3 neighbor addresses, loads nine `uint32_t` values through TMU direct memory lookup, performs signed integer arithmetic for gx/gy, computes absolute values and clamps to 255, then stores coalesced output through VPM/VDW. No shared memory or barriers are required. Protect VPM/VDW setup and store with mutex.

TEST_CASES:
Use deterministic image shapes `(1,1)`, `(2,3)`, `(7,5)`, `(16,16)`, `(17,9)`, `(31,19)`. Include one high-contrast checkerboard pattern, one smooth gradient, and one sparse impulse pattern across cases. Verify all pixels exactly and guard regions unchanged.

EXPECTED_OUTPUT:
Print `IMAGE_SOBEL_3X3_RUNTIME_SETUP max_width=31 max_height=19 allocations=1`. Print `IMAGE_SOBEL_3X3_CASE case=<id> width=<w> height=<h> mismatches=0 sentinel_mismatches=0 checksum=<value> launches=<count> allocations=1`. Final line: `VC4_TEST_RESULT name=image_sobel_3x3 status=PASS cases=6 total_mismatches=0 sentinel_mismatches=0 launch_failures=0 active_qpus=12 lanes=16 max_width=31 max_height=19 runtime_allocations=1 runtime_launches=6 elapsed_usec=<time>`.

EXPECTED_JSON_ORACLE:
Require exact `name`, `status`, `cases=6`, `total_mismatches=0`, `sentinel_mismatches=0`, `launch_failures=0`, `active_qpus=12`, `lanes=16`, `max_width=31`, `max_height=19`, `runtime_allocations=1`, and `runtime_launches=6`.

NON_GOALS:
This test does not use texture-format image sampling, bilinear filtering, shared-memory halo staging, or RGB/RGBA images. It is a naive raster `uint32_t` buffer kernel.

SPECIAL_NOTES:
Keep output exact integer to simplify oracle stability. If qasm integer abs/clamp is awkward, choose input patterns and output range so a simpler saturating logic is sufficient, but document the exact CPU reference.
